# Faithful Engine: offline research prototype

Status: development prototype. It is separate from FitCheck's product path and does not authorize live calls, deployment, or a new experiment. The named roles are separate injected **model** callbacks; deterministic Python manages the inputs, graph, bounds and records. This is inspired by, not a reproduction of, the separately trained components in Creswell and Shanahan. It does not expose a model's internal reasoning or certify entailment, factual truth, causation, human values or user approval.

## Reproduce the demonstration

From the repository root, using Python 3.9 or newer:

```sh
python -m reasoning_engine.demo
python -m reasoning_engine.demo --json
```

The [readable demo](faithful-engine-offline-demo-v1.md) and [complete synthetic packet](faithful-engine-offline-demo-v1.json) are generated by these commands. All responses in the packet are scripted fixtures, not previously obtained model results or real news. The packet has the full synthetic task, exact role requests, returned results, branches, trace, coverage, call count and $0 cost. The fake formatter makes an unsupported claim while the sidecar reports the omitted PCE obligation as not assessed. Structural omission is detected; semantic contradiction is **not** automatically checked.

## Boundaries and usage

- `engine.py` accepts `generate(stage, payload)`, and calls selection, inference, halter, value and formatter separately. Inference sees only selected texts plus its shared instruction when `prompts.bind_model` is used; weights and implicit model knowledge remain. The formatter sees the question and selected ancestry, while the evidence registry is retained. Graph depth describes recorded dependencies, not proven causal influence.
- `prompts.py` versions a sample instruction wrapper. Exact provider settings and prompts must be recorded by the caller. An arbitrary callback is not proof that this wrapper was used.
- `revision.py` reports changed evidence and potentially affected prior paths without changing an old outcome; new evidence always calls for a relevance review. `annotations.py` creates a separate candidate linked to an existing target. Neither grants human authority or activates changes.
- `renderer.py` is a readable summary of stored fields, not a complete or security-hardened disclosure filter. Treat saved requests, outputs and traces as private; do not include credentials. Missing source data and omitted evidence do not imply a source does not exist.
- `baseline.py` runs B1 and B+self-check separately. Each initial call sees the prepared task; the recheck sees that same task and only its own prior response. A failed recheck remains a failed final result and retains the earlier response in history. The callback must not carry hidden state between arms.
- `evaluator.py` compares declared inputs and counts runtime and review statuses separately, including unknown and failed assignments. A caller's claimed blind status or adjudication is not authenticated; previously viewed examples are development/regression, not an unexposed holdout. Model Value scores are not human value or quality scores.

## Local journal and current limitations

`executor.py` offers an optional local SQLite journal using Python's standard library; it adds a runtime file, not a server or a dependency. It durably reserves caller-specified exposure units and attempts before dispatch, records raw response bytes before JSON parsing, binds an explicit retry policy, retries only definitive HTTP 429 within bounds, and keeps an ambiguous attempt uncertain. This is an offline single-active-runner prototype, not a concurrency or live-safety guarantee. SQLite is not encrypted by this module: protect the entire journal and do not put credentials in request bytes.

The journal reports reserved exposure and attempt counts, not actual dollar billing, tokens, model identity, verified past spending, or provider invoices. If exposure units represent money, the caller must first subtract all prior commitments from the authorized limit, use conservative integer units, and separately reconcile actual usage and invoices. The engine and executor are independently usable and connected by an offline test; there is no bundled live provider adapter, automatic SDK retry enforcement, scheduler, or production authorization gate. Callback and journal errors need explicit monitoring. JSON decoding and engine schema checks are different from semantic review.

Input equality checks operate on supplied comparison records; they do not themselves freeze the provider, prove identical hidden model context, or authenticate reviewers. Quote-on/off and new-evidence/no-evidence conditions can be represented by separate declared inputs but there is no preregistered comparison matrix or forecast-outcome scorer. A sensitivity fixture changes a selected premise, but this does not prove logical correctness. Citation IDs are checked against selected evidence; source-text offsets and natural-language entailment are not verified. Role output is unreviewed, and evidence-change reports signal reassessment rather than automatically rerunning or declaring any old conclusion sound. Historical cases have not been re-run as new model evaluations.

## Before any live experiment

Select a model and accountable reviewers, explicitly approve the source and model operations, freeze the task and evidence versions, prior/quote conditions, comparison protocols and independent rubrics, set budget and retry authority, verify provider SDK retries are disabled, and protect raw artifacts. Any future change in evidence creates a new version. Test the actual provider adapter, accounting and operation recovery before authorizing use. Forecast calibration needs a predefined outcome protocol and resolved contracts. The current artifact has no new model or source results and establishes no performance, trust or alignment advantage.

## Seven requested design concerns

| Concern | What exists offline | What remains before a claim |
| --- | --- | --- |
| Comparison object | Five separate model callback roles, versioned instructions and structural projection checks | Supply and record a real model and actual request configuration; this is not the paper's trained-model reproduction |
| Task and result unit | Typed task and evidence, explicit required questions, separate model answer and coverage | Define a case-specific rubric and adjudicate semantic content |
| B and C comparability | Distinct B1, B+self and C; declared input comparison, independent call histories | Freeze assignments, settings, prior, quote, budgets and review protocol; compare actual recorded provider requests |
| Multi-step and causality | Explicit predecessor graph and dependency depth; offline premise-change fixture | Run predeclared counterfactuals on actual model outputs; sensitivity does not prove entailment |
| Independent assessment | Separate supplied review statuses, exposed-case and denominator reporting | Recruit or designate reviewers, preserve their provenance, and conduct independent assessments |
| Information and forecasts | Different evidence types; comparison records support declared quote/prior conditions | Preregister and run a factorial design if desired; evaluate resolved outcomes under a separate protocol |
| Audit and execution | Partial/complete event traces, demo packet, local journal and bounded 429 retry tests | Protect logs, integrate and test a live adapter and real usage accounting; no unknown call is automatically retried |
