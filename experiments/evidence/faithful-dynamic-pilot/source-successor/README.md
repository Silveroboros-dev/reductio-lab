# Source continuation bridge — offline implementation

The completed predecessor source effect is **not retried**. `inspect_predecessor` opens its SQLite database read-only with immutable mode under a shared lock and checks the exact database, old source contract, start/stop receipt hashes, budget and operation/event sequences. It binds the original full `source:case-01:serper` response and reproduces the fact that its news array contains 10 items although the source request specified 3. The persisted exception class is `PreflightError`; its message was not retained, so the reproduced condition is not presented as a verbatim exception receipt.

`create_successor(db, source_contract, started_receipt, stopped_receipt, successor_root=..., claim_path=..., ledger_contract_path=...)` validates the predecessor then atomically creates the fixed `CLAIM_PATH`; duplicate successor claims are refused. It creates one new SQLite ledger at the given create-only root. The frozen successor ledger contract is `../live-ledger-successor-contract-20261029.json`: carry $0.723593, source budget remaining $4.998, at most 17 remaining source attempts, 79 generation and 11 countTokens attempts already used, total caps $40, 835 and 767. A failed creation retains its one-shot claim for explicit reconciliation.

`PhaseLedger.source` admits exactly `source:case-02:serper` through `source:case-08:serper`, in the original frozen order, with the original exact request digests and the refreshed price-observation digest. It revalidates predecessor and claim each time before delegating to the existing one-shot accounting primitive. `summary()` shows the globally carried source attempt, while `receipt('source:case-01:serper')` returns the original complete receipt through a read-only bridge. Other receipts are from the successor. Unknown effects still stop and are not retried.

This bridge by itself never authorizes a live request, checks neither the refreshed price's factual validity nor provider billing guarantees, and cannot protect against callers bypassing the wrapper or mutating SQLite directly. Exact contract/context, one-shot transport and independent live challenge must be bound separately. The $0.25 reserve is an accounting cushion, not a provider-enforced cap. Physical source01 charge $0.002 is a receipt-backed observation, not a finalized invoice.

`PhaseLedger` is source-phase only: it refuses metadata, countTokens and generate calls. A separately challenged model-stage wrapper must explicitly verify successful capture of all seven, preserve both ledgers' receipts and activate model authority in the same successor ledger. No external call is made by this module or its tests.
