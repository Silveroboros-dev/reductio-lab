# Model-stage bridge — offline implementation

`model_stage.py` activates a model-only wrapper over the **same** source-successor SQLite; it does not run a provider or create a second ledger. Source and metadata calls remain prohibited. The original source01 receipt remains readable through the immutable predecessor bridge, with all 10 original news entries intact.

After the separate seven-source continuation completes, call `prepare_binding(phase, summary_path, source_contract_sha256)`. It requires the durable source-continuation started/completed events, exact summary hash, seven ordered successful and settled source receipts, source request and response byte hashes, billed amounts, exact predecessor and claim, the unchanged successor ledger contract, and total exposure/counters. It returns canonical JSON bytes of the eight-source receipt manifest; the caller must save those exact bytes create-only.

`activate_model_stage(phase, summary_path=..., source_contract_sha256=..., source_manifest_path=..., dataset_manifest_path=..., runner_path=..., model_contract_path=..., expected_model_contract_sha256=..., verify_challenge=...)` checks the frozen `faithful-model-stage-contract-v1`, exact binding dictionary and global caps and uses one SQLite transaction to record a unique `model_stage_started` event. The callback must independently validate the full run, not simply return true. Calling this adapter is not itself user or provider authority.

The returned `ModelLedger` exposes `receipt`, `summary`, `verify_predecessor`, `verify_source_binding`, `stop`, `count` and `generate`. Before every model operation it checks the frozen input/runner/summary/contract hashes, source receipt manifest and events; drift stops the ledger. It delegates model operations to the existing successor ledger, preserving prior cost and attempt counters. A saved claim and a stage-start marker prohibit automatic repeat of a model stage; reconciliation after a failure needs a separate authorized process.

There is no credential acquisition or provider transport in this module. Its receipt/manifest hashes identify local bytes but do not independently prove the source, correctness of the reported bill, whether the Grok-provided market data is real, human thesis confirmation, semantic correctness, actual invoice, or provider-enforced output/price ceilings. Caller must bind the model-stage module, protocol, ledger and transport versions and validate human/provenance/semantic review separately. The Python wrapper is not a security boundary against a caller mutating the database or bypassing the wrapper.
