# Unified budget ledger — offline prototype

This single-process primitive uses Python standard-library SQLite and an injected one-shot transport. No network access or live call was made by its development/tests. It records attempted model counts, generations and priced source requests in one journal, with source charge receipts and model token estimates. It is not a provider invoice and is not an authorization to run.

## Interface

`Ledger(path, contract, create=True)` creates a private, new directory and exclusive database, and pins the canonical contract bytes and SHA-256. On reopening use `create=False` with identical contract bytes. Contract example is `contract()` in `test_ledger.py`: $40 total cap, conservative prior exposure $0.721593, previous 79/11 model/count attempts, maxima 835/767, at most 18 source attempts/$5 sources, Gemini 3.8 Flash global, $1.50/$7.50 per million tokens gross as half-micro-dollar rates `3`/`15`, 16,384 input, 4,096 requested output, reserve 8,192 output+thought. Prices and the source-pin evidence must be independently validated; a 64-character digest is not proof of accuracy.

- `count(id, generation_body, transport)` dispatches `countTokens` with exactly the canonical top-level generation-body bytes and validates response `totalTokens`; model is separately pinned by the contract. This body shape is observed in the earlier successful FitCheck Gemini 3.8 runner and documented at https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/count-tokens . Count accounting assumes zero and requires a separately validated evidence digest for that assumption.
- `generate(id, generation_body, count_id, transport)` consumes one matching, previously successful count receipt, pre-reserves worst-case tokens at contract rates, persists request, received bytes and usage, and charges `totalTokenCount - promptTokenCount` as output including thinking. It stops if valid actual usage exceeds the reservation, or if the returned `modelVersion` is absent or inconsistent with the pinned model; incurred usage is recorded first. A matching alias does not prove immutable model weights. Model/tool configuration checks disallow tools, caching and body-supplied model.
- `metadata(id, request_bytes, reserve_micro, bound_evidence_sha256, transport, verify_bound=...)` is limited to one exact Serper `/news` `/v1/details` operation, uses the shared source/aggregate budget and requires a trusted verifier of the direct-account whole-request bound before effect. A callback returning true is an assertion and cannot authenticate its own evidence. Once an HTTP 200 is captured the actual metadata cost is unknown (`actual_micro=NULL`), the reserve remains and the ledger is stopped. In particular, an endpoint price quoted inside a details response is not metadata billing evidence. Reconciliation requires a separately authorized successor; this implementation has no resume/settlement bypass. If metadata cost can exceed the reserve, the user’s $40 exposure can be exceeded despite local accounting. The OneShotTransport allowlist does not currently support `/v1/details` and no live metadata request is enabled.
- `source(id, 'orthogonal', '/v1/run', request_bytes, quote, transport)` first requires provider `orthogonal`, endpoint `/v1/run`, and canonical bounded Serper `/news` JSON with exactly `body.q` and `body.num` (1–3), plus an empty `query`; it then validates a complete quote dictionary `{provider, endpoint, request_sha256, max_micro, evidence_sha256, expires_utc}`, a maximum $0.25 request quote and total source envelope. Records the full quote, request bytes, response, status and timestamps; a successful source receipt is accounted from the Orthogonal `priceCents` response. Invalid or absent charge keeps the reservation and stops. A non-200 is recorded as a completed effect, not inferred zero; it also keeps the reserve and stops.
- `receipt(id)` returns captured request/response, hashes, quote, timestamps, state and cost. `summary()` returns current exposure and counts. `stop(reason)` durably blocks further calls after a consumer detects a source integrity or schema failure. `close()` releases the exclusive lock.
- `transport(provider, endpoint, request_bytes) -> (http_status, response_bytes)` is supplied by the caller and **must perform exactly one operation, with no SDK/network retries or redirects**. The ledger cannot inspect opaque transport internals. Credentials and Authorization headers must not appear in request bytes.

Before transport, a SQLite transaction commits the price reservation and events `prepared`, `started`; after receipt it stores `succeeded` separately from semantic gates. An exception marks `uncertain`, retains its reservation and stops. On restart an in-flight effect becomes uncertain; a completed but unsettled effect remains succeeded and blocks. Existing operation IDs cannot be reused. Full quote and timestamps are preserved. No automatic retry, no automatic resolution of uncertain outcomes.

## Required external guarantees and limitations

1. The ledger works only if **every effect** is routed through this same single directory. Its `flock` excludes a second process opening that directory, not a process creating a different directory or provider calls elsewhere. Internal methods/DB are not a security boundary. Bind a unique runtime root in the run contract and use a single owner.
2. The price and output bounds are risk assumptions until bound to applicable provider/model/region/version/contract evidence. Google Gemini API documentation calls `max_output_tokens` a hard cutoff including thinking (https://ai.google.dev/gemini-api/docs/generate-content/thinking#token-limits-and-max_output_tokens); applicability to this exact Vertex endpoint and its usage semantics needs verification. If actual price or usage exceeds its quote, stopping happens **after** the provider has charged; there is no way for this local primitive to undo or prevent such a provider-side violation.
3. `countTokens` zero cost, exact count and source price metadata/quote must be checked against current provider docs and account; arbitrary or invented price pins are not acceptable. Price discrepancies, invalid JSON, missing usage or schema errors must stop, not be treated as free. The SHA by itself is not a quote validator.
4. SQLite FULL synchronous commits and exclusive access cover the declared local setup; crash/power-loss/storage-provider guarantees and independently sealed evidence are not established. Request/response bytes are private; don't submit credentials or externally publish the DB.
5. The injected transport and the orchestration code still need real endpoint integration, independent review, exact run-contract binding, case cohorts, source evidence and a consistent output/review schema before using this for the experiment.
