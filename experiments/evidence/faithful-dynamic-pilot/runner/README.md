# Offline four-arm runner

This is a preparation artifact, **not a live-approved runner**. It joins the existing controller, three baselines, model protocol and SQLite ledger through an injected transport. It never creates a network client or sources credentials. A caller must separately establish the identity and one-shot behavior of any real transport, hard price bounds, authority, and an independently challenged frozen execution contract.

`preflight(manifest, dataset_root, ledger, verify_human, verify_capture)` validates all eight inputs before model calls. The manifest uses `faithful-dynamic-pilot-manifest-v1` and exactly two `dev`, six `test` rows, each with unique `case_id`, `event_group_id`, `input_sha256`, `input_path`, `human_attestation_path`, `human_attestation_sha256`. Each case JSON contains `task`, `replay`, and `attachments` containing relative `path` and `sha256`. Each evidence item has `content_sha256` and exactly one nonempty `verbatim_parts` value equal to the evidence text. It must equal one complete decoded JSON string value or the complete UTF-8 source text; joining or truncating values is forbidden. Surrounding fields and source context still require review. Bindings establish file integrity, not truth, completeness, source independence, or provenance.

The current active FitCheck label guide's exact bytes must be a separately selectable initial-evidence item. Each contract ID must occur in initial evidence text. A `paid_api` action has a `source_effect_id` naming a succeeded and settled source in the very same ledger. The raw response is rehashed and must match each evidence item delivered for that action; quoted cost must match that source effect. A `manual_capture` is a separate case: it binds a user-relayed Grok claim to the exact permitted source bytes, report, request URL, reported UTC time and HTTP status. The source provenance is user-reported, not independently verified; both its action quote and external personal cost remain unknown (`null`), not zero. It does not synthesize a paid ledger receipt. Actual physical acquisition cost remains in the shared ledger; per-arm replay is a shadow action, not another provider call. The runner requires 1–2 actions per case.

`verify_human(attestation_bytes, case, manifest_row)` and `verify_capture(case, manifest_row)` are required injected admission callbacks. They are intentionally unimplemented. Returning True is merely the caller's assertion. A real verifier must verify exact human decision provenance, thesis and scope and bind the source bytes and relevant user report. For a manual capture, it must preserve that the direct HTTP, capture time, and status are user-reported rather than independently verified. A fabricated reviewer, locally made assertion, checksum alone, or timestamp inferred from `updated_time` is insufficient. These callbacks may not perform an unregistered provider effect. No code here certifies semantic novelty or independent human review.

`run(...)` validates every case first, then uses a deterministic Latin rotation of arm order over sorted events, dev first. It binds manifest/schedule/protocol hashes and a runner-started marker in the ledger, writes a durable slot-started record before model dispatch, and disallows runner re-entry against that ledger. Every model callback uses the same `model_protocol`, `ledger.count` and `ledger.generate` once, then parses one JSON result. This is enforced only for calls that actually go through the injected ledger and transport; the wrapper cannot prevent hidden internal retries in an untrusted transport. It writes create-only per-slot results and a summary; there is no automatic retry or resume. A ledger Stop halts remaining slots, which are counted `not_attempted`. A parse/protocol failure is technical, not an incorrect semantic answer. Human semantic adjudication is explicitly absent.

Fairness caveats: C emits labels and a separate structured trace, baseline additionally emits explanations/citations; an outcome-blind reviewer projection must be defined before analysis. The initial guide and IDs don't ensure the model selects them or preserves the required ID in its inference. A frozen input plus identical limits is not a proof of equal effective compute, source freshness, or valid evidence-to-answer semantics. Assertions to establish policy, novel cohorts, source captures, reviewer identity and event provenance remain external blockers.

The runner saves canonicalized manifest/schedule artifacts and binds their raw hashes to a ledger marker along with runner, protocol, controller, harness and policy file digests. This private digest chain is not an independent seal. It does not bind `ledger.py`, a real one-shot transport, price-contract evidence, human/capture verifier implementations, Python/dependency versions, or prove that already-imported code matches files subsequently hashed. All require separate live execution-context freeze and independent challenge; source overlaps and semantic novelty require review. Exact text shared between initial and replay evidence is rejected, but paraphrased or contextual leakage is still possible. Only using this code does not make an execution live-ready.
