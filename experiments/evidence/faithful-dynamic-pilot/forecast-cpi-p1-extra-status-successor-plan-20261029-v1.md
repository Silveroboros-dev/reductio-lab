# CPI P1: contingency for up to ten additional status checks

Status: offline contingency only. The current P1 process and its ledger remain untouched. The extra checks are an allowance, not a target. This plan grants no execution authority by itself.

## Trigger and scope

Only consider the successor if the existing run durably stops because it has consumed the previously authorized 28 source attempts and still needs a market-status observation to finish the original P1. If the current run completes, use none of the additional allowance. If it stops for another reason, diagnose that reason first; this source allowance does not by itself authorize replaying model outputs, repairing another output, or resolving an uncertain effect.

The user has raised the combined source-attempt ceiling from 28 to 38. The existing $60 total cap and global 835 generation / 767 countTokens attempt caps stay unchanged. The extra ten are CPI market-status checks only, for the same frozen ticker and rules, not news, a canary, trading, or unrelated searches. Use only as many as the original experiment needs. Keep any tighter preexisting model-stage and 429 budgets, including the shared 20 extra physical model attempts and up to three additional attempts per confirmed-429 operation, inclusive of attempts already consumed.

## Freeze after the running process ends

1. Wait for the process to exit, close its SQLite connection, and persist its output and stopped status. Capture a read-only snapshot and exact SHA-256 of the final database, run input, logs, frozen source/model contracts, recovery contract, and durable partial outputs. Never copy or alter a live SQLite file as if it were a complete journal.
2. Reconcile every effect, count, response, HTTP status, settlement, reserve, state transition, and journal marker against the existing immutable parents. Carry the exposure including historical unknown-cost reserves and each confirmed-429 reserve. Account for all source observations and model calls, including those from preceding series. Confirm that no effect is started, uncertain, or missing a durable receipt. An unverified or unknown effect blocks continuation; do not infer it failed.
3. Reconstruct the controller and B arms using byte-equal offline replay of every already successful request/response. Preserve the strict C/no-news result as unparseable and the one-character repaired derivative as post-hoc. If a countTokens call succeeded but its generation was never attempted, bind its historical count receipt to the exact generation bytes without calling countTokens again. A prior valid HTTP 200 generation is never sent again. The first usable candidate is final: no best-of or semantic resampling.
4. If the last operation is a confirmed, durably recorded 429 and the preauthorized retry limits still allow continuation, any continuation must use the exact historical request bytes and carry the prior operation attempt number and the already used shared retry allowance. A timeout, missing receipt, schema-invalid HTTP 200, or uncertain effect is not a 429. A successful countTokens response remains reusable for generation; do not repeat it. If this cross-ledger case cannot be proven, stop and report a partial result.
5. Produce a create-only successor accounting contract linked by hash to the final stopped journal, exact replay proof, repaired derivative, and original protocol. Its starting exposure and global counters must be derived from the final journal rather than assumed. Its source capacity is at most `min(10, 38 - already_consumed_sources)` and counts every physical provider attempt; stop on budget or source cap. Preserve existing model per-stage limits, remaining 429 allowance, frozen tasks, prices, resolution rules, and no-news isolation.

## Status-only stage

Freeze up to ten distinct operation identifiers, starting after the last consumed ID, for exactly the same Orthogonal `kalshi` `GET /markets` payload with `tickers=KXCPI-26OCT-T0.2` and no additional market/filter. Each identifier represents a new observation, never an automatic retry of a failed or uncertain operation. The number in the contract is a maximum: execute one only when needed to maintain the original <=300-second status guard or final status verification.

Before freezing, obtain a fresh read-only UI price observation and bind its timestamp, expiry and exact provider request. A displayed price is an estimate, not an invoice or a provider-enforced price cap. Retain $0.15 per source attempt before dispatch and settle actual billed `chargedPriceCents`; if billing data is missing or inconsistent, preserve the reserve and stop. A positive, consistently reported fee is accounted within the approved total, rather than automatically assumed free. Preserve the existing source-budget accounting where applicable. Refuse provider starts that would breach the total cap even with the reserve; the reserve cannot prevent the provider charging more.

The status receipt must establish the same contract, exact frozen rules, active/unresolved state, and acquisition time. Orthogonal is an intermediary; upstream cache age is not independently established. The model receives the frozen quote only in the conditions already specified by the original protocol; status refreshes must not leak current quotes into no-news inputs. Retain the <=300-second guard, the frozen market-close deadline, and the explicit BEA embargo timing assumption.

## Review and dispatch

Use a single new ledger with separately frozen accounting and executable contracts. Independently review exact source scope, byte-equal replay, original and successor receipt binding, cost carry, 429 attempt continuity, status freshness and no-news isolation. Test offline with fake transports: no successful or uncertain replay; historical count reuse; 429 budget across both ledgers; duplicate status ID rejection; billed/missing/mismatch handling; 38-source and $60 ceilings; stale/resolved-market stop; and partial reporting. Do not open a live provider connection until the final successor is independently reviewed and its accounting ledger is bound. Any continuation that cannot recover a prior completed arm without repetition is partial, not a silently restarted experiment.
